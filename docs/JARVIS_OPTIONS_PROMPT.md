# Prompt สำหรับทีม Jarvis: เลือกบัญชี กลุ่ม และเครื่อง ตอนสั่งงาน Scrap / Autopost

## เป้าหมาย

พนักงานสั่งงานจาก Jarvis ที่เดียว ตอนกดสั่ง ต้องเห็นข้อมูลเหล่านี้:

1. บัญชี Facebook แต่ละบัญชีวันนี้โพสต์ไปแล้วกี่ครั้ง โควต้าเท่าไหร่ หรือโดนพักอยู่ไหม
2. ชื่อกลุ่ม Facebook จริง และผลย้อนหลังของแต่ละกลุ่ม (โพสต์กี่ครั้ง ได้คอมเมนต์/เบอร์เท่าไหร่)
3. แต่ละเครื่อง (worker) ออนไลน์ไหม มีคิวงานค้างกี่งาน และพนักงาน**เลือกเครื่องเองได้** ทั้งงานโพสต์และงาน Scrap (เช่น เครื่องหลักคิวเต็มแต่งานรีบ)
4. บัญชี JobThai / JobBKK ตัวไหนพร้อมใช้

ถ้าบัญชีเต็มหรือถูกพัก ให้ขึ้น popup เตือนก่อนส่งคำสั่ง

ระบบ So Scraping มี API ให้แล้ว Jarvis ต้องทำ 4 อย่าง:
1. แสดงตัวเลือกจาก API options
2. บันทึกค่าที่พนักงานเลือกลงใน `job_snapshot`
3. เรียก API start ให้งานเริ่มทันที พนักงานไม่ต้องเข้าระบบ So Scraping
4. ดึงผลงานจาก API status มาแสดงในหน้าใบงานของ Jarvis

## 1. ดึงตัวเลือก

```
GET https://api-scraper.sosiamraj.com/api/integrations/jarvis/options
x-api-key: <JARVIS_INTEGRATION_KEY>
```

- key ทีม So Scraping จะส่งให้แยก ห้ามใส่ใน frontend ให้เรียกจาก backend ของ Jarvis
- ดึงใหม่ทุกครั้งที่เปิดฟอร์มสั่งงาน (ข้อมูลเปลี่ยนตลอด ห้าม cache)
- key ผิดหรือไม่ส่ง ได้ 401

### ความหมายของ `status`

**accounts** (บัญชี Facebook)

| status | ความหมาย | Jarvis ต้องทำ |
|---|---|---|
| `ready` | พร้อมโพสต์ | เลือกได้ |
| `busy` | กำลังอุ่นเครื่อง (ไม่โพสต์) / กำลังโพสต์งานอื่น / มีงานรอคิว — `warning` บอกว่าอันไหน งานใหม่ต่อคิว | เลือกได้ แสดง `warning` เป็นข้อมูล |
| `full` | โพสต์ครบโควต้าวันนี้แล้ว | popup เตือนด้วย `warning` ถ้าพนักงานยืนยันจะสั่งต่อก็ส่งได้ |
| `paused` | ระบบพักบัญชีไว้ (เช่น โพสต์ไม่ผ่านติดกันหลายครั้ง) | popup เตือน และไม่ให้เลือก |
| `worker_offline` | เครื่องหลักของบัญชีนี้ (`worker`) ออฟไลน์ | popup เตือน ให้เลือกเครื่องอื่นที่ออนไลน์แทน |
| `needs_verification` | Facebook ขอยืนยันตัวตนบัญชีนี้ ต้องมีคนไปทำที่เครื่องก่อน (เพิ่ม 3 พ.ย. 2569) | ไม่ให้เลือก แสดง `warning` (มีวันเวลาที่เริ่มติด) |

บัญชีที่ยังไม่มีเครื่องประจำ (`worker` เป็น `null`) จะได้ `ready` พร้อม `warning` ว่ายังไม่มีเครื่องประจำ ให้เลือกได้ แล้วบังคับให้พนักงานเลือกเครื่องในขั้นถัดไป (ส่ง `worker` ใน `job_snapshot`) สถานะ `no_worker` เลิกส่งแล้ว

**scrape_accounts** (บัญชี JobThai / JobBKK)

| status | ความหมาย | Jarvis ต้องทำ |
|---|---|---|
| `ready` | พร้อมใช้ | เลือกได้ |
| `full` | เว็บนั้นเปิดดูโปรไฟล์ครบโควต้าวันนี้แล้ว | popup เตือน |
| `cooldown` | บัญชีพักชั่วคราว | ไม่ให้เลือก |
| `disabled` | ปิดใช้งาน | ไม่ให้เลือก |

ใช้ข้อความใน `warning` เป็นข้อความใน popup ได้เลย ระบบเขียนเป็นภาษาไทยไว้แล้ว

### กลุ่ม

- แสดง `name` ถ้า `name` เป็น `null` แปลว่าบอทยังไม่เคยเข้าไปอ่านชื่อ ให้แสดง `fb_group_id` แทน แล้วต่อท้ายว่า "ยังไม่มีชื่อ"
- กลุ่มไม่ได้ผูกกับบัญชี ทุกบัญชีเลือกได้ทุกกลุ่ม แสดง `groups` ทั้งหมดให้เลือก
  - `accounts[].group_ids` และ `groups[].account_ids` จึงมีครบทุกตัว (กรองตามสองช่องนี้เหมือนเดิมก็ได้ผลเท่ากัน)
  - `home_group_ids` / `home_account_ids` คือกลุ่มที่ตั้งไว้กับบัญชีนั้นในหน้าตั้งค่า ใช้ติดป้าย "กลุ่มประจำ" ได้ ไม่ต้องใช้กรอง
  - ถ้าบัญชียังไม่ได้เป็นสมาชิกกลุ่ม บอทจะกดเข้าร่วมให้ได้รอบละไม่เกิน 5 กลุ่ม กลุ่มที่ต้องรอแอดมินอนุมัติจะขึ้น "ยังไม่ได้เข้ากลุ่ม" ในผล
- `last_posted_at` เอาไว้บอกว่ากลุ่มนี้โพสต์ล่าสุดเมื่อไหร่
- `stats_30d` ผลย้อนหลัง 30 วัน ใช้เรียงหรือติดป้าย "กลุ่มที่ได้คนเยอะ":
  - `attempts` จำนวนครั้งที่สั่งโพสต์ลงกลุ่มนี้ / `posted` จำนวนครั้งที่โพสต์สำเร็จ
  - `comments` คอมเมนต์รวม / `phone_leads` จำนวนคนที่ทิ้งเบอร์ในคอมเมนต์
  - ตอนนี้ตัวเก็บคอมเมนต์ยังอ่านคอมเมนต์รายคนได้ไม่ครบ `comments` กับ `phone_leads` อาจต่ำกว่าจริง ทีม So Scraping กำลังแก้ ให้ใช้ `posted` เป็นหลักไปก่อน

### เครื่อง (worker)

พนักงานเลือกเครื่องได้เองทั้งงานโพสต์และงาน Scrap ระบบจะส่งงานไปเครื่องที่เลือก ไม่สลับไปเครื่องอื่นให้

- `workers` เรียงจากเครื่องที่ออนไลน์และคิวว่างที่สุดก่อน แสดง `online`, `load`, `post_queue`, `scrape_queue` ให้พนักงานเห็นว่าเครื่องไหนคิวแน่น
- `kinds` บอกว่าเครื่องนั้นรับงานอะไรได้: `autopost` = โพสต์ Facebook, `scraper` = Scrap ให้แสดงเฉพาะเครื่องที่รับงานประเภทนั้นได้
- ถ้าไม่เลือกเครื่อง: งานโพสต์ไปที่ `accounts[].worker` (เครื่องหลักของบัญชี) งาน Scrap ไปเครื่องที่ระบบตั้งไว้

**ข้อควรเตือนเมื่อเลือกเครื่องให้งานโพสต์**
- บัญชี Facebook ต้องล็อกอินไว้บนเครื่องนั้น ดูจาก `accounts[].session_workers` (หรือ `workers[].fb_account_ids`)
- ถ้าเลือกเครื่องที่ไม่อยู่ใน `session_workers` ให้ popup เตือนว่า "บัญชีนี้ยังไม่เคยล็อกอินบนเครื่องนี้ บอทจะล็อกอินใหม่ และ Facebook อาจขอยืนยันตัวตน" ถ้าพนักงานยืนยันก็ส่งได้
- ถ้าเครื่องที่เลือก `online = false` งานจะค้างรอจนเครื่องนั้นเปิด ให้ popup เตือนก่อนส่ง

## 2. ส่งค่าที่เลือกกลับมาใน `job_snapshot`

ยังใช้ตาราง `jarvis_rm.job_posting_requests` เหมือนเดิม เพิ่มแค่ฟิลด์ใน `job_snapshot`

**คำขอ Autopost (`request_type = 'content'`)**

| ฟิลด์ | ชนิด | บังคับไหม | หมายเหตุ |
|---|---|---|---|
| `group_ids` | string[] | บังคับ (มีอยู่แล้ว) | ใช้ `groups[].id` ไม่ใช่ `fb_group_id` |
| `account_id` | string | ไม่บังคับ (ใหม่) | `accounts[].id` ถ้าไม่ส่ง ระบบจะเลือกบัญชีที่ผูกกลุ่มให้เอง |
| `worker` | string | ไม่บังคับ (ใหม่) | `workers[].name` ที่ `kinds` มี `autopost` ถ้าไม่ส่ง ใช้ `accounts[].worker` |

ถ้าส่ง `account_id` มา บัญชีนั้นต้องไม่ถูกพัก ไม่งั้นงานจะขึ้นปัญหาให้แก้ในหน้างานโพสต์ กลุ่มใน `group_ids` ต้องเป็น `groups[].id` ที่มีในระบบ กลุ่มที่ไม่มีในระบบจะถูกตัดออก

**คำขอ Scrap (`request_type = 'scraping'`)**

| ฟิลด์ | ชนิด | บังคับไหม | หมายเหตุ |
|---|---|---|---|
| `scrape_connector_ids` | string[] | บังคับถ้าจะเริ่มงานเอง (ใหม่) | `scrape_accounts[].id` เรียงตามลำดับที่อยากใช้ ระบบใช้ตัวแรกที่พร้อม |
| `scrape_worker` | string | ไม่บังคับ (ใหม่) | `workers[].name` ที่ `kinds` มี `scraper` ทุกรอบของงานนี้จะรันที่เครื่องนี้ ถ้าเครื่องไม่พร้อม งานจะไม่เริ่มและขึ้นเหตุผลให้เห็น |

## 3. เริ่มงานทันที

หลังบันทึก `job_posting_requests` (status = `pending`) แล้ว ให้เรียก:

```
POST https://api-scraper.sosiamraj.com/api/integrations/jarvis/start
x-api-key: <JARVIS_INTEGRATION_KEY>
Content-Type: application/json

{ "request_no": "OPL6910068" }
```

ระบบจะเริ่มงานตามค่าใน `job_snapshot` เท่านั้น ไม่เลือกอะไรแทน

**ผลลัพธ์**

| HTTP | ความหมาย | Jarvis ต้องทำ |
|---|---|---|
| 200 | เริ่มแล้ว | แจ้งพนักงานว่าเริ่มงานแล้ว |
| 409 | ใบนี้เริ่มไปแล้ว | ไม่ต้องทำอะไร เรียกซ้ำได้ ไม่สร้างงานซ้ำ |
| 422 | ข้อมูลไม่ครบหรือติดปัญหา (เช่น ยังไม่เลือกบัญชี Scrap, บัญชีไม่ได้ผูกกลุ่ม) | แสดง `error` ให้พนักงานเห็น คำสั่งยังค้างอยู่ แก้แล้วเรียกใหม่ได้ |
| 404 | ไม่พบเลขใบนี้ | ตรวจว่าบันทึกสำเร็จก่อนเรียก |
| 401 | key ผิด | ตรวจ key |

**ตัวอย่างผลลัพธ์ 200**

งานโพสต์:
```json
{ "ok": true, "type": "content", "request_no": "LBM6903001", "queue_id": "mvoz...", "worker": "SONB-RM009", "preflight_queued": false }
```
- `preflight_queued` เป็น `false` เสมอ ระบบเลิกทดสอบก่อนโพสต์แล้ว สั่งแล้วงานเข้าคิวโพสต์เลย ถ้าบัญชีล็อกอินไม่ได้จะรู้จากผลรอบโพสต์

งาน Scrap:
```json
{ "ok": true, "type": "scraping", "request_no": "OPL6910068", "task_id": "7d97...", "queued": true, "message": null }
```
- `queued: false` แปลว่าสร้างงานแล้วแต่ยังเริ่มไม่ได้ (เช่น เครื่องที่เลือกยังไม่เปิด Scrape) เหตุผลอยู่ใน `message` ให้แสดงให้พนักงานเห็น

## 4. ดูผลงาน

```
GET https://api-scraper.sosiamraj.com/api/integrations/jarvis/status?request_no=OPL6905114
x-api-key: <JARVIS_INTEGRATION_KEY>
```

- ขอได้ครั้งละหลายใบ คั่นด้วยจุลภาค ไม่เกิน 20 ใบ เช่น `?request_no=OPL6905114,OPL6910068`
- ใช้ตอนเปิดหน้าใบงาน หรือรีเฟรชทุก 1–2 นาทีระหว่างงานยังไม่จบ (`run_status` เป็น `queued` / `running` หรือ Scrap `group` เป็น `working`)
- ยอดไลก์และคอมเมนต์อัปเดตทุกราว 2 ชั่วโมง (รอบเก็บคอมเมนต์ของเครื่อง)

**ตัวอย่างงานโพสต์ (`type: "content"`)**
```json

```

| ฟิลด์ | ความหมาย |
|---|---|
| `run_status` | `queued` รอเครื่อง · `running` กำลังโพสต์ · `completed` จบรอบ · `failed` รอบนี้ล้ม · `null` ยังไม่เริ่ม |
| `groups[].status` | `posted` ขึ้นในกลุ่มแล้ว (มีลิงก์) · `pending_approval` โพสต์แล้ว รอแอดมินกลุ่มอนุมัติ · `unconfirmed` กดโพสต์แล้วแต่ยังไม่เจอโพสต์ในกลุ่ม (ห้ามแสดงว่าสำเร็จ) · `failed` ไม่สำเร็จ (เหตุผลใน `error`) · `waiting` ยังไม่ถึงคิว |
| `summary.posted` / `pending_approval` / `unconfirmed` | นับตาม `groups[].status` — แสดงแยกกัน อย่ารวมเป็น "สำเร็จ" ก้อนเดียว |

| `issues` | เหตุผลที่ยังเริ่มงานไม่ได้ (ถ้ามี) |

## 5. ลำดับในฟอร์มที่แนะนำ

1. เปิดฟอร์ม → เรียก options
2. **Autopost**: เลือกบัญชี (แสดง `posted_today/daily_cap` และสถานะ) → เลือกกลุ่มของบัญชีนั้น (แสดงชื่อกลุ่มกับ `stats_30d`) → เลือกเครื่อง (ค่าเริ่มต้น = `accounts[].worker` แสดง `load` ทุกเครื่อง)
3. **Scrap**: เลือกบัญชี JobThai / JobBKK (แสดงสถานะ และ `platform_used_today/platform_cap`) → เลือกเครื่อง (เฉพาะเครื่องที่มี `scraper` แสดง `load`)
4. กดส่ง → popup เตือนก่อนถ้า: บัญชีเป็น `full` / `paused` / `worker_offline`, เครื่องที่เลือกออฟไลน์, หรือบัญชียังไม่ได้ล็อกอินบนเครื่องที่เลือก
5. บันทึก `job_posting_requests` พร้อม `job_snapshot` ตามข้อ 2
6. เรียก `POST /start` ตามข้อ 3 แล้วแสดงผลให้พนักงานเห็น
7. หน้าใบงานใน Jarvis ดึง `GET /status` ตามข้อ 4 มาแสดงผลรายกลุ่มหรือความคืบหน้า Scrap

## 6. ฉบับ 3 พ.ย. 2569: หน้าสั่งต้องตัดสินแทนคนสั่ง

คนที่สั่งงานไม่ใช่ Dev หน้าที่เขาคือสั่ง หน้าสั่งจึงต้องทำ 4 อย่างนี้ให้เอง เหตุการณ์จริงวันนี้: คนสั่งเลือกบัญชีที่ถูกพักอยู่ 2 ใบติด (OPL6910064/65) และเลือก 14 กลุ่มที่ใบเดิมเพิ่งลงเมื่อวาน ระบบตอบกลับเป็นข้อความยาว ๆ ว่า "ต้องเว้น 2 วัน" โดยไม่มีอะไรบนจอบอกก่อนกด

So Scraping ส่งข้อมูลครบแล้ว (ขึ้นเว็บ 3 พ.ย.) Jarvis ต้องเอามาแสดงและบังคับตามนี้

### 6.1 บัญชี: ค่าเริ่มต้นคือบัญชีที่ใช้ได้ บัญชีที่ใช้ไม่ได้ต้องบอกว่าทำไม

- ช่องเลือกบัญชี **ค่าเริ่มต้น = บัญชีแรกที่ `recommended: true`** (พร้อมโพสต์ ไม่มีคำเตือน และล็อกอินอยู่บนเครื่องที่ออนไลน์) ถ้าไม่มีสักบัญชี ให้ช่องว่างแล้วขึ้นข้อความ "ตอนนี้ไม่มีบัญชีที่พร้อมโพสต์" พร้อมเวลาที่บัญชีตัวแรกจะกลับมาใช้ได้ (`paused_until` ที่ใกล้สุด)
- ทุกบัญชีในรายการต้องมี **คำสถานะ + สี** ตาม `status` (ห้ามใช้สีอย่างเดียว):
  - `ready` → "พร้อมโพสต์ · เหลือ N โพสต์วันนี้" (N = `remaining_today`) เขียว
  - `busy` → "มีงานค้าง ต่อคิวได้" เหลือง เลือกได้
  - `full` → "ครบโควต้าวันนี้ (x/y)" เหลือง เลือกได้แต่เตือน
  - `worker_offline` → "เครื่อง X ออฟไลน์" เหลือง เลือกได้แต่ต้องเลือกเครื่องอื่น
  - `paused` → "ถูกพัก ใช้ได้ <วัน เวลา>" (จาก `paused_until`) แดง **เลือกไม่ได้**
  - `needs_verification` → "ต้องยืนยันตัวตนที่เครื่อง ตั้งแต่ <วัน เวลา>" แดง **เลือกไม่ได้**
- `status` ที่ Jarvis ไม่รู้จัก ให้ถือว่า **เลือกไม่ได้** และแสดง `warning` ตรง ๆ (กันกรณี So Scraping เพิ่มสถานะใหม่แล้ว Jarvis ปล่อยให้เลือก)

### 6.2 กลุ่ม: เลือกได้ไม่เกินเครดิตที่เหลือ และกลุ่มที่เลือกไม่ได้ต้องบอกเหตุ

- **จำนวนกลุ่มที่ติ๊กได้สูงสุด = `accounts[].remaining_today` ของบัญชีที่เลือก** (เช่น เหลือ 15 ติ๊กได้ 15) ติ๊กครบแล้วช่องที่เหลือเป็นสีเทา แสดงตัวนับ "เลือกแล้ว 12/15"
  - ถ้าคนสั่งต้องการมากกว่านั้น ให้สั่งเป็นใบใหม่ด้วยบัญชีอื่น ไม่ใช่ติ๊กเกิน (เกินแล้ว worker หยุดเองที่เพดาน กลุ่มที่เหลือไม่ได้โพสต์)
- เรียก options **พร้อมเลขใบขอ**: `GET /options?request_no=OPL6910065` ระบบจะเติม `groups[].repost_wait` ให้กลุ่มที่ใบนี้เพิ่งลงไม่ถึง 2 วัน
  - `repost_wait != null` → แสดง "ใบนี้เพิ่งลง <last_posted_at> โพสต์ได้อีก <available_at>" สีเทา **ไม่ติ๊กให้เป็นค่าเริ่มต้น** (ติ๊กเองได้ แต่รอบนี้ระบบจะข้ามกลุ่มนั้น ดู 6.4)
- สถานะรายกลุ่มของบัญชีที่เลือก (`accounts[].group_status`) และ `groups[].blocked` ใช้แบบเดิม: `recommended: false` = ไม่ติ๊กให้เป็นค่าเริ่มต้น แสดง `label` + `detail` + ลิงก์ `url`
- **ค่าเริ่มต้นของกลุ่ม** = กลุ่มของธุรกิจเดียวกับใบงาน (`department`) ที่ `recommended` และไม่มี `repost_wait` เรียงตาม `stats_30d.posted` มากไปน้อย ตัดที่ `remaining_today`

### 6.3 เครื่อง: ค่าเริ่มต้นคือเครื่องที่ไม่มีปัญหา

- ช่องเลือกเครื่อง **ค่าเริ่มต้น = เครื่องที่ `recommended.post: true`** (งานโพสต์) หรือ `recommended.scrape: true` (งาน Scrap) = ออนไลน์และคิวเบาสุด
- เครื่องที่ `online: false` แสดง "ออฟไลน์ ตั้งแต่ <last_seen>" เลือกไม่ได้เป็นค่าเริ่มต้น
- ถ้าบัญชีที่เลือกไม่ได้ล็อกอินบนเครื่องนั้น (`session_workers` ไม่มีชื่อเครื่อง) ขึ้นคำเตือนเดิม "บอทจะล็อกอินใหม่ Facebook อาจขอยืนยันตัวตน"

### 6.4 ผลตอบกลับตอนสั่ง: ไม่ปฏิเสธทั้งใบอีกแล้ว

`POST /start` ของงาน content ตอนนี้ **ข้ามกลุ่มที่ใบนี้เพิ่งลงไม่ถึง 2 วัน แล้วโพสต์กลุ่มที่เหลือ** คำตอบเพิ่มช่อง:

```json
{
  "ok": true, "type": "content", "request_no": "OPL6910065", "queue_id": "…",
  "group_count": 3,
  "skipped_groups": [
    { "id": "mvhm…", "name": "หางานขับรถ หาคนขับรถ กทม Bangkok", "last_posted_at": "2026-11-02T03:12:00.000Z", "available_at": "2026-11-04T03:12:00.000Z" }
  ],
  "message": "ข้าม 1 กลุ่มที่เพิ่งลง (หางานขับรถ หาคนขับรถ กทม Bangkok) โพสต์ได้อีก 4 พ.ย. 10:12"
}
```

- `message != null` → แสดงให้คนสั่งเห็นทันทีหลังกดสั่ง (ไม่ใช่ซ่อนใน log) และเก็บไว้แสดงในหน้าใบงานด้วย (`GET /status` ส่ง `run_message` ข้อความเดียวกัน)
- ยังได้ 422 เฉพาะเมื่อ **ทุกกลุ่ม** ที่เลือกเพิ่งลง ข้อความจะบอกวันเวลาที่โพสต์ได้อีก ให้แสดงตรง ๆ

### 6.5 เสร็จเมื่อ

1. เปิดฟอร์มสั่งโพสต์ตอนที่มีบัญชีถูกพัก → บัญชีนั้นเป็นสีแดง มีคำว่า "ถูกพัก ใช้ได้ <เวลา>" ติ๊กไม่ได้ และช่องบัญชีถูกเลือกเป็นบัญชีที่พร้อมให้แล้ว
2. เลือกบัญชีที่เหลือ 15 โพสต์ → ติ๊กกลุ่มได้ 15 กลุ่ม กลุ่มที่ 16 เป็นสีเทา
3. สั่งใบเดิมซ้ำวันถัดไป → กลุ่มที่เพิ่งลงขึ้น "โพสต์ได้อีก <วัน เวลา>" และไม่ถูกติ๊กให้ตั้งแต่แรก
4. กดสั่งแล้วมีกลุ่มถูกข้าม → เห็นข้อความ "ข้าม N กลุ่ม…" บนจอทันที และหน้าใบงานก็เห็น

ทดสอบ: `curl -H "x-api-key: <key>" "https://api-scraper.sosiamraj.com/api/integrations/jarvis/options?request_no=LBM6903001"` ต้องมี `accounts[].recommended`, `accounts[].needs_verification_since`, `workers[].recommended`, `groups[].repost_wait`

## 7. ฉบับ 4 พ.ย. 2569: กลุ่มมี 2,000+ แล้ว แยกประเภท ราชการ / เอกชน

คลังกลุ่มเพิ่มจาก 37 เป็น 2,400+ กลุ่ม (นำเข้าจากชีต "ราชการ" ของทีม Online) ทุกกลุ่มมีช่องใหม่ `groups[].sector`:
- `"private"` = เอกชน (กลุ่มชุดเดิม 37 กลุ่ม)
- `"government"` = ราชการ (กลุ่มที่นำเข้าใหม่)

Jarvis ต้องทำ
1. หน้าเลือกกลุ่ม **ให้เลือกประเภทก่อน** (ปุ่มสลับ "เอกชน / ราชการ" ค่าเริ่มต้นตามลูกค้าของใบงาน ถ้าไม่รู้ให้เริ่มที่เอกชน) แล้วค่อยแสดงกลุ่มของประเภทนั้น ห้ามแสดงทั้ง 2,400 กลุ่มในรายการเดียว
2. มี **ช่องค้นหา** ชื่อกลุ่ม/จังหวัด ในรายการกลุ่ม
3. ค่าเริ่มต้นของกลุ่ม (ข้อ 6.2) ยังใช้ `department` + `recommended` + `stats_30d.posted` เหมือนเดิม แต่กรองตาม `sector` ที่เลือกก่อน
4. กลุ่มราชการส่วนใหญ่ยังไม่มีสถิติ (`stats_30d` เป็น 0 และ `group_status` ว่าง = "ยังไม่เคยลอง") ไม่ต้องถือว่าเป็นกลุ่มเสีย

## 8. ฉบับ 4 พ.ย. 2569 (แทนลำดับในข้อ 5–7): ลำดับหน้าสั่งโพสต์ที่เจ้าของเคาะ

หลักการ: **คนสั่งเห็นเฉพาะของที่ใช้ได้อยู่บน ๆ ของที่ใช้ไม่ได้ให้ตกลงล่างและกดไม่ได้** ไม่ซ่อน (จะได้รู้ว่ามีอยู่) · บัญชีที่ "ยังไม่เคยล็อกอิน" ถือว่า**ใช้ได้** แค่ยังไม่เคยถูกใช้

1. **เลือกบัญชี** — เรียงตาม `accounts[].sort_rank` (0 พร้อมและล็อกอินอยู่ · 1 พร้อมแต่ยังไม่เคยล็อกอิน · 2 ใช้ได้แต่มีเงื่อนไข · 3 ใช้ไม่ได้) ค่าเริ่มต้น = ตัวแรกที่ `recommended: true` · แถวที่ `sort_rank = 3` แสดงสีแดงพร้อมคำ (ถูกพัก ใช้ได้ <เวลา> / ต้องยืนยันตัวตน) และ**เลือกไม่ได้** · แสดงเครดิตที่เหลือ `remaining_today` ทุกแถว
2. **เลือก BU ของกลุ่ม** — ปุ่ม LBD / LBA / LM ต้องกดเลือกเอง ไม่ตั้งค่าเริ่มต้นให้ (เจ้าของ: ถ้าขึ้นมาเลยคนจะไม่เลือกอันอื่น) · แล้วเลือกประเภท เอกชน / ราชการ (`groups[].sector`)
3. **เลือกจังหวัด** — รายการจากค่าใน `groups[].provinces` ของ BU/ประเภทที่เลือก · **ไม่เลือก = ขึ้นทุกกลุ่ม**
4. **เลือกกลุ่ม** — เมื่อเลือกจังหวัด แสดงเฉพาะกลุ่มที่ `provinces` มีจังหวัดนั้น ตามด้วยกลุ่ม `nationwide: true` · กลุ่มที่ `provinces = []` (ยังไม่ระบุ) ขึ้นเฉพาะตอนไม่เลือกจังหวัด · ติ๊กได้ไม่เกิน `remaining_today` ของบัญชีที่เลือก (ข้อ 6.2) · กลุ่มที่ `repost_wait` หรือ `recommended: false` ตกลงล่างและไม่ติ๊กให้
5. **เลือกเครื่อง** — ค่าเริ่มต้น `workers[].recommended.post` · เครื่องออฟไลน์ตกลงล่าง
6. กดสั่ง → แสดง `message` จาก /start ทันที (ข้อ 6.4)

ช่องใหม่ใน /options: `accounts[].sort_rank`, `groups[].provinces` (array, อาจหลายจังหวัด), `groups[].nationwide`, `groups[].sector`

### 8.1 ประเภทงานของกลุ่ม (เพิ่ม 4 พ.ย. 2569)

`groups[].job_types` = ประเภทงานที่กลุ่มรับ (เลือกได้หลายอย่าง): ช่าง · ธุรการ · ประชาสัมพันธ์ · ขับรถนายไทย · ขับรถนายต่างชาติ · ขับรถส่วนกลาง · Valet · `[]` = ยังไม่ระบุ
- ในข้อ 4 (เลือกกลุ่ม) ให้มีปุ่มกรองประเภทงาน ค่าเริ่มต้น = ประเภทที่ตรงกับตำแหน่งในใบงาน (เช่น ใบ "พนักงานขับรถ นายไทย" → ขับรถนายไทย) ถ้าเดาไม่ได้ให้ไม่กรอง
- กลุ่มที่ `job_types = []` ขึ้นเฉพาะตอนไม่ได้กรองประเภทงาน

## 9. ฉบับ 4 พ.ย. 2569: ใบที่ค้างหรือไม่สำเร็จ ต้องสั่งใหม่ได้จากปุ่ม Autopost / Scrap บนการ์ด

ปัญหาวันนี้: ไม่สำเร็จ 6 ใบ ค้าง 2 ใบ คนสั่งไม่รู้ว่าต้องทำอะไรต่อ เพราะหน้าต่าง Autopost / Scrap (`AutopostDialog`) มีทางตัน 2 จุด
- ใบสถานะ `pending` ที่ So Scraping เริ่มไม่ได้ (เช่น บัญชีถูกพัก) ขึ้นว่า "มีคำสั่งโพสต์ค้างอยู่ · รอ — รอให้เสร็จก่อนถึงสั่งใหม่ได้" และปุ่ม **ส่ง Autopost** กดไม่ได้ตลอด
- ใบ `rejected` สั่งใหม่ได้ แต่หน้าต่างนี้ไม่บอกเหตุ (`OrderPostButton` บอกจาก `notes` แล้ว แต่ `AutopostDialog` ยังไม่บอก)

ให้ทำในหน้าต่าง Autopost / Scrap ตามสถานะใบล่าสุดของใบขอนั้น

1. **`pending` (ค้าง)**
   - เรียก `GET /api/integrations/jarvis/status?request_no=<เลขใบ>` แล้วแสดง `issues[]` เป็นคำ เช่น "ยังเริ่มไม่ได้: บัญชี Burkhart Debe ถูกพักอยู่"
   - ปุ่ม **ส่งให้ So Scraping อีกครั้ง** (ใช้ retry เดิมของ `SoStartLine`) สำหรับกรณีแก้ที่ So Scraping แล้ว
   - ปุ่ม **ยกเลิกใบนี้แล้วสั่งใหม่** → PATCH `status = 'cancelled'`, `notes = 'ยกเลิกโดย <อีเมลคนกด>'` ทำได้เฉพาะตอนยังเป็น `pending` (ถ้าเปลี่ยนเป็น `in_progress` แล้ว ให้บอกว่า So Scraping เริ่มงานแล้ว ยกเลิกไม่ได้) · ยกเลิกเสร็จเปิดฟอร์มสั่งต่อทันที
2. **`rejected` (ไม่สำเร็จ)**
   - บรรทัดแรกแสดง "ไม่สำเร็จ" + เหตุจาก `notes` (ตัด "ตีกลับ: " ข้างหน้าออก)
   - ปุ่มส่งเปลี่ยนชื่อเป็น **สั่งใหม่**
3. **ฟอร์มสั่งใหม่ (ทั้งข้อ 1 และ 2)** เติมข้อความประกาศ กลุ่ม และโหมดโพสต์จากใบเดิมไว้ให้ · บัญชีตั้งต้น = ตัวแรกที่ `recommended: true` ตามข้อ 8 ข้อ 1 · ถ้าบัญชีเดิมยังใช้ได้ก็ไม่ตั้งเป็นค่าเริ่มต้น (บัญชีเดิมคือเหตุที่ไม่สำเร็จบ่อยที่สุด: Facebook จำกัดการโพสต์)
4. **`in_progress`** คงเดิม (รอให้จบ)
5. **คำบนจอ** เปลี่ยน "ไม่รับงาน" เป็น "ไม่สำเร็จ" ทุกที่ (`SO_STATUS_LABEL.rejected`, `SO_FACET_LABEL.rejected`, `soNoticeTitle`) เพราะ So Scraping ตีกลับเมื่อโพสต์หรือค้นไม่สำเร็จ ไม่ได้ปฏิเสธงาน
6. **การ์ดบนบอร์ด** ใบที่ไม่สำเร็จหรือค้าง แสดงป้ายสถานะ + เหตุ 1 บรรทัดบนการ์ดเลย ไม่ต้องเปิดหน้าต่างก่อนถึงรู้

So Scraping ไม่ต้องแก้: `issues` มีใน /status แล้ว · ใบ `cancelled` So Scraping ไม่หยิบไปทำ และหน้า "คำสั่งงาน" ของ So Scraping นับแยกเป็น "ยกเลิก"

**เสร็จเมื่อ** (ทดสอบผ่านหน้าจอจริง)
- เปิดการ์ด OPL6910066 → เห็น "บัญชี Burkhart Debe ถูกพักอยู่" → กด ยกเลิกใบนี้แล้วสั่งใหม่ → ฟอร์มมีข้อความและกลุ่มเดิม บัญชีเป็นตัวที่ใช้ได้ → ส่ง → หน้างานโพสต์ของ So Scraping มีรอบใหม่
- เปิดการ์ด SQ6911003 → เห็น "ไม่สำเร็จ" พร้อมเหตุ → กด สั่งใหม่ → ได้รอบใหม่ด้วยบัญชีอื่น
- ไม่มีคำว่า "ไม่รับงาน" เหลือบนจอ

## 10. ฉบับ 5 พ.ย. 2569: ของที่ใช้ไม่ได้ ต้องเลือกไม่ได้ตั้งแต่แรก

เหตุ: 4 พ.ย. ใบโพสต์ไม่สำเร็จ 3 ใบติด (OPL6904029 · OPL6906009 · OPL6907119) เพราะเลือกบัญชีที่ Facebook จำกัดมาแล้ววันละครั้งตั้งแต่ 2 พ.ย. และใบ Scrap บางใบสั่งด้วยข้อมูลที่ค้นไม่ได้ (ตำแหน่ง "ช่าง" · อายุ 20–20 ปี)
หลักการ: **ของที่ So Scraping บอกว่าใช้ไม่ได้ = กดเลือกไม่ได้ ไม่ใช่แค่ไม่ติ๊กให้** และบอกเหตุเป็นคำข้างรายการ (แทนข้อ 8 ข้อ 4 ที่เขียนว่า "ไม่ติ๊กให้")

1. **บัญชี** — `accounts[].status` ไม่ใช่ `ready` (ถูกพัก · ต้องยืนยันตัวตน · ครบโควต้า) = เลือกไม่ได้ แสดง `warning` ตรง ๆ
   - บัญชีที่โดน Facebook จำกัดถูกพักตามครั้งที่โดนใน 30 วัน (9 พ.ย. 2569: ครั้งแรก 7 วัน · ครั้งที่ 2 14 วัน · ครั้งที่ 3 ขึ้นไป 28 วัน · พ้นพักแล้ววันแรกโพสต์ได้ 1 กลุ่ม) `warning` จะขึ้นเช่น "บัญชีถูกพักถึง 23 พ.ย. 17:10 (Facebook จำกัดการโพสต์ของบัญชีนี้ (ครั้งที่ 2 ใน 30 วัน) — พัก 14 วัน …)"
   - `remaining_today` / `daily_cap` ของแต่ละบัญชีไม่เท่ากันทุกวัน (สุ่ม 3 ถึงเพดาน และบัญชีที่เพิ่งพ้นพักได้ 2–4 กลุ่ม/วัน) — Jarvis ต้องอ่านค่าจาก /options ทุกครั้ง ห้ามจำเลข 8 ไว้เอง
2. **กลุ่ม** (หลังเลือกบัญชีแล้ว) — ติ๊กไม่ได้ ตกลงล่าง พร้อมคำบอกเหตุ เมื่อ
   - `accounts[บัญชีที่เลือก].group_status[]` ของกลุ่มนั้นมี `recommended: false` → แสดง `label` (แอดมินพักกลุ่ม · ต้องเข้ากลุ่มเอง (มีคำถาม) · รอแอดมินรับเข้ากลุ่ม · บัญชีนี้เปิดกลุ่มไม่ได้ · เปิดกลุ่มแล้วไม่เจอช่องโพสต์ · Facebook ไม่รับโพสต์)
   - `groups[].blocked` ไม่ใช่ null → แสดง `blocked.label`
   - `groups[].repost_wait` ไม่ใช่ null → แสดง "ใบนี้เพิ่งลงกลุ่มนี้ ลงได้อีก <available_at>"
   - สถานะกลุ่มผูกกับบัญชี: เปลี่ยนบัญชีแล้วต้องคำนวณใหม่ กลุ่มที่ติ๊กไว้แต่ใช้ไม่ได้กับบัญชีใหม่ ให้เอาติ๊กออกเองพร้อมบอก
3. **ใบ Scrap** — อ่าน `scrape_rules` จาก /options แล้วปิดปุ่มส่ง Scrap พร้อมเหตุ เมื่อ
   - ชื่อตำแหน่ง (หลังตัดช่องว่าง) ตรงกับคำใน `scrape_rules.too_generic_titles` (ตอนนี้: ช่าง · พนักงาน · เจ้าหน้าที่ · ผู้ช่วย) → "ชื่อตำแหน่ง "ช่าง" กว้างเกินไป เว็บหางานไม่รับ ใส่ให้ชัด เช่น ช่างไฟฟ้า ช่างอาคาร ช่างแอร์"
   - อายุต่ำสุดหรือสูงสุดอยู่นอก `scrape_rules.age_min`–`age_max` (15–80) · ต่ำสุดมากกว่าสูงสุด · หรือห่างกันน้อยกว่า `scrape_rules.min_age_span` (2) → เช่น "ช่วงอายุ 20–20 ปี แคบเกินไป ต้องห่างกันอย่างน้อย 2 ปี"
   - So Scraping ตรวจซ้ำตอน /start ด้วยกติกาเดียวกัน: ถ้าหลุดมา จะตอบ 422 `สั่ง Scrap ไม่ได้: <เหตุ>` และตีกลับใบใน Jarvis เป็น rejected พร้อม notes เดียวกัน

## 11. ฉบับ 9 พ.ย. 2569: บัญชี 3 สี (แทนข้อ 6.1 และข้อ 10 ข้อ 1 เฉพาะเรื่องบัญชี)

เจ้าของ: "ใช้ได้เขียว รอยืนยันตัวตนเหลือง พักหรือบล็อคแดง" · บัญชีที่รอยืนยันตัวตนต้องเลือกได้ เพื่อสั่งโพสต์ 1 กลุ่มแล้วไปยืนยันที่เครื่อง

| สี | `accounts[].status` | คำบนจอ | เลือกได้ |
|---|---|---|---|
| เขียว | `ready` | "ใช้ได้ · เหลือ N โพสต์วันนี้" (`remaining_today`) | ได้ |
| เขียว | `busy` | "ใช้ได้ · มีงานค้าง งานนี้ต่อคิว" | ได้ |
| เหลือง | `needs_verification` | "รอยืนยันตัวตน · ต้องมีคนอยู่หน้าเครื่อง <worker> ตอนงานเริ่ม" | ได้ **ไม่เกิน 1 กลุ่มต่อใบ** |
| แดง | `paused` · `full` · `worker_offline` · `no_worker` · สถานะที่ไม่รู้จัก | `warning` ตรง ๆ | ไม่ได้ |

- เรียง เขียว → เหลือง → แดง (ในสีเดียวกันเรียงตาม `sort_rank`) · ค่าเริ่มต้นยังเป็นบัญชีแรกที่ `recommended: true` (เหลืองไม่เป็นค่าเริ่มต้น)
- เลือกบัญชีเหลืองแล้ว: กลุ่มติ๊กได้ 1 กลุ่ม ตัวนับ "เลือกแล้ว 1/1" และขึ้นคำเตือนใต้ช่องบัญชีว่า "งานนี้จะเปิด Facebook บนเครื่อง <worker> ต้องมีคนยืนยันตัวตนในหน้าต่าง Chrome ภายใน 5 นาทีหลังงานเริ่ม ถ้าไม่ทัน งานจะล้มและส่งกลุ่มให้บัญชีอื่นโพสต์แทน"
- ยืนยันผ่าน = So Scraping ล้างสถานะเอง รอบหน้าบัญชีขึ้นเขียว
- กติกากลุ่ม (ข้อ 10 ข้อ 2) และใบ Scrap (ข้อ 10 ข้อ 3) ใช้เหมือนเดิม

**เสร็จเมื่อ** (ทดสอบผ่านหน้าจอจริง)
- หน้าต่าง Autopost เห็น 3 สีพร้อมคำ บัญชีเหลืองกดเลือกได้ บัญชีแดงกดไม่ได้
- เลือกบัญชีเหลืองแล้วติ๊กกลุ่มที่ 2 ไม่ได้

## 12. ฉบับ 9 พ.ย. 2569: สั่งไม่ได้ต้องบอกว่าเพราะอะไร

เจ้าของ: "ก็ต้องบอกสิว่าสั่งไม่ได้ เพราะอะไร" — เดิมหน้าต่าง Autopost ขึ้นแค่ "ตอนนี้ไม่มีบัญชีที่พร้อมโพสต์ · บัญชีแรกใช้ได้ 12 พ.ย. 08:20"

## 13. ฉบับ 11 พ.ย. 2569: การ์ด "5. โพสต์ลงกลุ่ม Facebook" ในภาพรวมงานสรรหา

เจ้าของสั่ง: ตารางโพสต์รายกลุ่ม (ใครสั่ง · บัญชีไหน · กลุ่มไหน · งานอะไร · วันที่ · ผล · ลิงก์) ไปโชว์ที่แท็บ **ภาพรวม** ของหน้างานสรรหา (`/jobs/board?view=dashboard` → `RecruitOverview` → `RecruitStuckBody`) เป็นการ์ดที่ 5 ต่อจาก "4. ช่องทางไหนทำได้ดี" ใช้ `OverviewCard` แบบเดียวกับการ์ด 1–4 · ทุกคนที่เห็นภาพรวมเห็นทุกใบ ไม่ต้องเพิ่มสิทธิ์

### ก่อนเริ่ม: แก้ที่อยู่ So Scraping

`app_outbound_api_keys` แถว `so-scraping` ยังเป็น `https://so-scraping.vercel.app` ซึ่งปิดไปตั้งแต่ 6 พ.ย. 2569 ต้องเป็น `https://api-scraper.sosiamraj.com` (เจ้าของแก้จากหน้า ตั้งค่า → การ์ด So Scraping ได้ ไม่ต้องแก้โค้ด) · `SO_DEFAULT_BASE_URL` ในโค้ดควรเปลี่ยนตามด้วย

### ดึงข้อมูล

เรียกจากเซิร์ฟเวอร์ Jarvis เท่านั้น (ใช้ `loadSoKey()` แบบ `fetchSoStatusOf` ห้ามส่ง key ไปหน้าจอ) แล้วเปิดเส้นของ Jarvis เองให้หน้าจอเรียก

```
GET {base_url}/api/integrations/jarvis/post-groups?from=2026-10-01&to=2026-11-11&bu=LBD&page=1&page_size=10
x-api-key: <key เดิม>
```

- `from` / `to` = ช่วงวันที่ที่ภาพรวมเลือกอยู่ (วันที่สั่ง เวลาไทย รวมวันสุดท้าย) ไม่ต้องทำตัวเลือกวันใหม่
- `bu` = BU ที่ภาพรวมเลือกอยู่ (ฝ่ายของคนสั่ง) · "ทุก BU" = ไม่ส่ง `bu`
- `page_size` สูงสุด 200 · การ์ดใช้ 10
- `counts` = จำนวนแยกสถานะของทั้งช่วง ผลรวม = `total` · `statuses` = ลำดับและคำของ 7 สถานะ ใช้คำเดียวกับแท็บ "เนื้อหาของคุณ" ใน Facebook: เผยแพร่แล้ว · รอดำเนินการ · ปฏิเสธแล้ว · ลบออกแล้ว · ไม่สำเร็จ · ไม่ได้โพสต์ · รอคิว (12 พ.ย. 2569: กดโพสต์แล้วแต่โพสต์ไม่ขึ้น รวมอยู่ในไม่สำเร็จ เหตุอยู่ใน `error` · ปฏิเสธแล้ว/ลบออกแล้ว ตัวเก็บคอมเมนต์เช็กจากแท็บให้ `post_link` เป็น null) · อ่านจาก `statuses` เสมอ อย่าฝังรายการคำไว้ในโค้ด Jarvis
- **ห้ามคำนวณสถานะเอง** ใช้ `status` / `status_label` / `error` ตามที่ส่งไป (นิยามเดียวกับหน้า So Scraping, Excel และหน้าใบสั่ง)

แต่ละแถวใน `rows[]`:

```json
{
```
