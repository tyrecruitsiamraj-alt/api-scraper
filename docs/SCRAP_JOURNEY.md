# Journey ของงาน Scrap: จาก Jarvis สั่ง จนคนสรรหาได้ผู้สมัคร

ไล่จากโค้ดจริง 4 พ.ย. 2569 (main · ตัวแก้ชิปตำแหน่ง/เพศ/อายุ รอขึ้น RM009) ครอบคลุม JobBKK และ JobThai ทุกทางแยก รวมสิ่งที่เว็บปลายทางทำเองที่เรามองไม่เห็น

ใครทำอะไร: **Jarvis** (คนสั่ง) → **เว็บ So Scraping** (Vercel) → **ฐานข้อมูล** → **เครื่อง RM009** (worker ช่อง scraper-1, scraper-2) → **เว็บ JobBKK / JobThai** → **Ollama** (AI วางแผนคำค้น + OCR) → กลับมาที่เว็บให้คนสรรหาตรวจ

หน้าใบงานบนเว็บแสดง 7 ขั้น: รับคำขอ → รอคิว → ล็อกอิน → ค้นหาและคัดโปรไฟล์ → อ่านเอกสาร (OCR) → เติมข้อมูล → ตรวจรับ · ด้านล่างแตกเป็น 20 ขั้นจริง

---

## ขั้น 1 รับคำขอ (Jarvis → เว็บ)

1. **Jarvis กดสั่ง** → ยิง `POST /start` พร้อมเลขใบขอ Jarvis รอคำตอบไม่เกิน 10 วินาที
   - คีย์ผิด → 401 · ไม่มีเลขใบ → 400 · ไม่พบใบ → "ไม่พบคำสั่ง X" · ใบไม่ได้อยู่สถานะรอ → 409 "เริ่มไปแล้ว"
   - ระบบอ่านแถวล่าสุดของเลขใบนั้น ไม่ดูชนิด: ถ้ามีใบโพสต์เลขเดียวกันใหม่กว่า จะถูกจัดเป็นงานโพสต์แทน (จุดอ่อน)
2. **เลือกบัญชีค้น** จากที่พนักงานเลือกใน Jarvis (ลองทีละบัญชี ตัวแรกที่ใช้ได้ชนะ)
   - ไม่ได้เลือก → 422 "ยังไม่ได้เลือกบัญชี Scrap"
   - บัญชีปิด / พักชั่วคราว (cooldown) / JobBKK ไม่มีสิทธิ์ Resume Search Talent (เคยล้มใน 24 ชม.) → 422 พร้อมเหตุผล
   - **โควตาเปิดดูต่อวันไม่ถูกเช็กตรงนี้** (เช็กตอนรันจริง ขั้น 8) Jarvis จึงสั่งผ่านทั้งที่โควตาเต็มแล้ว
3. **สร้างใบงาน** จากข้อมูลใบขอ (เติมจาก ERP และใบโพสต์เลขเดียวกันถ้ามี)
   - ตำแหน่ง: จากใบขอ ไม่เอาถ้าเป็นแค่ "3 อัตรา" · จังหวัด: ใช้ตามคำที่ส่งมาตรง ๆ ไม่เทียบรายชื่อจังหวัด (ที่อยู่ยาว ๆ จะกลายเป็นจังหวัด) · เพศ: "ไม่ระบุ/ทุกเพศ/ชายหญิง" = ไม่กรอง · วุฒิ: แปลงเป็น 7 ระดับ · อายุ: ต้องอยู่ 15–80 และต่ำสุด ≤ สูงสุด ไม่งั้น 422
   - **เงินเดือน (กติกา 3 พ.ย.)**: ใส่เป็นกรอบเฉพาะเมื่อใบขอเขียน "ไม่เกิน N" (สูงสุด) หรือ "N ขึ้นไป / N+" (ต่ำสุด) · เลขรายได้เฉย ๆ หรือช่วง = ไม่กรอง
   - เป้าจำนวนคน: จาก ERP (คงเหลือ/อัตรา) ไม่มี = **20** (จำนวนใน Jarvis ไม่ถูกใช้)
   - สั่งซ้ำเลขเดิม: ถ้าใบงานไม่ได้รัน/รอคิวอยู่ จะแก้เกณฑ์ทับแล้วรีเซ็ตสถานะตรวจรับ
   - **สถานะใน Jarvis ถูกเปลี่ยนเป็น "กำลังทำ" ตรงนี้** ก่อนเข้าคิว ถ้าเข้าคิวไม่สำเร็จ Jarvis กดสั่งซ้ำไม่ได้อีก (409) ต้องมากด "รันตอนนี้" ในเว็บเรา (จุดอ่อน)

## ขั้น 2 รอคิว (เว็บ → ฐาน → RM009)

4. **เข้าคิว** · เข้าไม่ได้ = ใบงานค้าง "ยังไม่เริ่ม" พร้อมเหตุ:
   - ไม่มีเครื่องพร้อม (ไม่มี heartbeat ใน 2 นาที) → "ยังไม่มีเครื่องค้นหาผู้สมัครที่พร้อมรับงาน" (เกิด 3 พ.ย. 08:10 ใบ wongsakon 5 ใบ ค้างทั้งวัน ไม่มีใครรับต่อเมื่อเครื่องกลับมา)
   - เครื่องที่เลือกใน Jarvis ออฟไลน์ → "เครื่อง X ที่เลือกไว้ยังไม่พร้อม" ไม่สลับเครื่องให้
   - Jarvis ได้รับ `queued:false` + ข้อความนั้น · หน้าใบงานขั้น "รอคิว" แต่ **ไม่แสดงเหตุผลที่ค้าง** (แสดงเฉพาะตอน error/partial)
5. **เครื่องรับงาน** worker ถามคิวทุก 3 วินาที ส่ง heartbeat ทุก 15 วินาที
   - รับได้เมื่อ: ถึงเวลา · ชื่อเครื่องตรง (หรือไม่ระบุ) · บัญชีนั้นไม่มีงานอื่นกำลังรัน (1 บัญชี 1 งาน) · ใบงานไม่ถูกปิด
   - งานที่ค้าง "กำลังรัน" เกิน 10 นาทีโดยไม่มีคิว → error "ค้างนานเกิน 10 นาที… กดรันตอนนี้"
   - ใบที่ได้คนครบเป้าแล้ว → จบทันที ไม่ค้นซ้ำ

## ขั้น 3 ล็อกอิน (RM009 → Ollama → เว็บงาน)

6. **วางแผนคำค้น** (หน้าเว็บยังโชว์เป็น "ล็อกอิน · กำลังเตรียมคำค้นจากเนื้องาน")
   - เนื้องานสั้น ≤ 40 ตัวอักษรและตรงพจนานุกรม → ใช้พจนานุกรม ไม่เรียก AI
   - ไม่งั้นเรียก AI: มีคีย์ Anthropic → claude-haiku · ไม่มี → Ollama (ลองโมเดลได้ไม่เกิน 3 ตัว ตัวละ 180 วิ)
   - AI คืนตำแหน่งชุดหนึ่ง (ตัดคำอังกฤษ/ยาวเกิน 22 ตัวอักษรทิ้ง) + "Second Brain" เติมคำที่เคยได้ผลอีกไม่เกิน 5 คำ + ตัดคำที่เคยเปิด ≥ 20 ใบแต่ผ่าน 0
   - **เกณฑ์สายงาน** = ชุดตำแหน่งที่ AI ให้ (คนที่ตำแหน่ง/ประวัติงานไม่มีคำพวกนี้จะตก "ไม่ตรงสายงาน")
   - เงื่อนไขจากเนื้องาน: เป็น "ต้องมี" จริงเฉพาะใบขับขี่/ใบรับรอง หรือเมื่อเนื้องานมีคำว่า ต้องมี/จำเป็นต้อง/ไม่รับ/ไม่พิจารณา (กรณีนี้ **ทุก** เงื่อนไขกลายเป็นต้องมี) ที่เหลือเป็นคะแนนเสริม
   - AI ล้ม: มีชื่อตำแหน่งในใบ → ค้นด้วยชื่อนั้น · ไม่มี → error "AI แปลงเนื้องานเป็นชื่อตำแหน่งไม่ได้…"
7. **เริ่มรอบค้น** เป้ารอบ = เป้า − คนที่ได้แล้ว · เกณฑ์แบ่งเป็น "ส่งไปเว็บ" (ตำแหน่ง คำค้น จังหวัด อายุ เงินเดือน สาขา · JobBKK ส่งเพศด้วย) กับ "คัดในเครื่อง" (วุฒิ เพศ)
8. **ด่านโควตา/พัก** ก่อนล็อกอิน
   - ใบถูกปิดโดยคน → "หยุดแล้ว คนกดปิดงานนี้"
   - บัญชีถูกพัก → cooldown "บัญชี X ถูกพักอยู่ เว็บเพิ่งจำกัดการใช้งาน"
   - โควตาวัน: JobBKK **200** / JobThai **1,000** ใบต่อวัน (นับจากรอบที่จบแล้วเท่านั้น รอบที่กำลังวิ่งยังไม่นับ) เต็ม → cooldown "daily cap reached" แล้วคิวลองซ้ำอีก 2 ครั้งใน 1.5 นาที แล้ว error (ไม่รอข้ามวันให้)
9. **ล็อกอิน** จำกัด 5 นาที
   - **JobBKK**: เปิด Chrome จริง (ซ่อนไว้นอกจอ) ล็อกอินใหม่ทุกครั้ง · ถ้าเว็บถาม "ล็อกอินซ้อน" บอทกด "ตกลง" ยึด session เสมอ (ใครล็อกอินอยู่จะหลุด) · เจอ CAPTCHA และไม่มีตัวแก้ → หยุดบัญชี "เจอหน้ายืนยันตัวตน… ให้คนตรวจบัญชี" · ล็อกอินไม่ติดใน 45 วิ / รหัสผิด / ไม่มีสิทธิ์ → error พร้อมภาพ `.auth/jobbkk-postlogin.png`
   - **JobThai**: ไม่มีหน้าต่าง ใช้ session เดิมถ้ายังใช้ได้ ไม่งั้นล็อกอินใหม่ (120 วิ) · CAPTCHA → error
   - ล็อกอินล้ม = รอบ failed → ใบ error → คิวลองใหม่ (ขั้น 15)

## ขั้น 4 ค้นหาและคัดโปรไฟล์ (RM009 → เว็บงาน → ฐาน)

10. **ค้นรายชื่อ** จำกัด 3 นาทีต่อรอบ · ขอจำนวนมากกว่าเป้า (×3 สูงสุด +300) เพราะต้องคัดในเครื่องอีก
    - **JobBKK** (หน้า Resume Search Talent · Normal Search): ใส่ตามลำดับ ชิปตำแหน่ง (≤ 3 ชิป) → Keyword → สาขาอาชีพ → จังหวัด → วุฒิ → เพศ → เงินเดือน → อายุ → รูปแบบงาน → ประสบการณ์ → เริ่มงาน
      - **ตรวจกลับทุกช่อง**: ชิปตำแหน่งต้องเห็นป้ายหรือตัวนับ N/3 ขยับ (รอรายการแนะนำ 6 วิ ลอง 2 รอบ) · จังหวัดต้องเห็นชื่อในกล่อง · เพศ/อายุ/วุฒิ/เงินเดือน ต้องเห็นค่าในกล่องของแถว
      - **ตำแหน่งหรือจังหวัดไม่ติด = หยุดทันที** ไม่กดค้น ไม่เปิดเรซูเม่ ไม่เสียโควตา error `JOBBKK_FILTER_NOT_APPLIED` + ภาพหน้าจอ `.auth/jobbkk-filter-position-<เวลา>.png` · ช่องอื่นไม่ติด = ข้ามแล้วจดไว้ (ไม่หยุด)
      - ได้ 0 คน → ผ่อนตัวกรองทีละชั้น: (1) เริ่มงาน/ประสบการณ์/รูปแบบงาน (2) เงินเดือน/อายุ (3) วุฒิ/เพศ (4) สาขา/Keyword · **ไม่เคยถอดตำแหน่งกับจังหวัด**
      - ยังไม่พอ → ใช้ AI Search ของ JobBKK เติม (พิมพ์เป็นประโยค ไม่มีตัวกรอง ไม่เช็กลำดับใหม่สุด)
      - เรียง "อัปเดตล่าสุด" ถ้าเช็กไม่ได้จะกดแล้วไปต่อโดยไม่รับประกัน · เปิดหน้าถัดไปได้ถึง 40 หน้า
    - **JobThai**: ไม่มีฟอร์ม ส่งเป็น URL: ตำแหน่ง, Keyword, รหัสภาค/จังหวัด, ช่องเงินเดือน (7 ช่วง), ช่องอายุ (<20 / 20–25 / 25–30 / 30–35 / >35), อัปเดตใน 30 วัน
      - **ส่งช่องเงินเดือน/อายุเฉพาะเมื่อช่วงที่ขอตกในช่องเดียว** (อายุ 25–50 = ไม่ส่ง = ไม่จำกัด) · เพศ/วุฒิไม่ส่ง คัดในเครื่อง
      - **จังหวัดที่ไม่รู้จักรหัส = ค้นทั้งประเทศเงียบ ๆ** (ไม่หยุด) · สมุทรปราการใช้รหัส 0659 ได้ 0 คนทุกครั้งตั้งแต่ ก.ย. (41 รอบ) ยังไม่รู้ว่ารหัสผิดหรือเว็บไม่มีคน
      - หลายตำแหน่ง (คั่นด้วยบรรทัด/,/หรือ) ค้นทีละตำแหน่ง เว้น 0.6–1.4 วิ
      - โดน 429/403/ข้อความบล็อก → รอบ cooldown พักบัญชี 2 ชม.
    - รายชื่อที่ใบนี้เคยเปิดแล้ว ตัดออก
11. **เปิดดูทีละคน** จนกว่าจะได้คนผ่านเกณฑ์ครบเป้า (คนละไม่เกิน 3 นาที เว้น 0.6–1.4 วิ)
    1. คนกดปิดใบ → หยุด
    2. เปิดหน้า: JobBKK เปิดในเบราว์เซอร์ (รอ 45 วิ + ลองซ้ำ 2 ครั้ง) · JobThai ดึง HTML
    3. หลุด session (ถูกเตะ/หน้าล็อกอิน) → ล็อกอินใหม่ ได้ถึง 8 ครั้งต่อรอบ
    4. **โปรไฟล์ไม่ครบ** (ชื่อ เพศ อายุ ที่อยู่ การศึกษา ประวัติงาน) → ดึงซ้ำ 2 ครั้ง ยังไม่ครบ = ไม่เก็บ นับเป็น "โปรไฟล์กรอกไม่ครบ" (เช้า 3 พ.ย. 21–29 จาก 60 คนตกข้อนี้ ส่วนใหญ่ขาดประวัติงาน — ยังไม่รู้ว่าคนไม่กรอกจริงหรือตัวอ่านอ่านไม่ออก) · **เสียโควตาแล้ว**
    5. **คัดเกณฑ์**: ตก = ไม่ตรงสายงาน / พื้นที่ไม่ตรง / วุฒิต่ำกว่า / เพศไม่ตรง / อายุนอกช่วง / เงินเดือนเกินกรอบ (ดูเลขต่ำสุดที่เขาขอ) · ขาดหลักฐาน (เช่น ไม่มีใบขับขี่ในเรซูเม่) = "ต้องตรวจเพิ่ม" ไม่ตก · คะแนน 60–100
    6. **ขอดูเบอร์** เฉพาะคนผ่าน/ต้องตรวจเพิ่ม: JobThai กดดูเบอร์ (ใช้เครดิตเว็บ) · JobBKK อ่านจากหน้าที่เปิดอยู่ ไม่มีปุ่ม
    7. ผ่านแต่ไม่มีเบอร์และอีเมล → ลดเป็น "ต้องตรวจเพิ่ม (ไม่มีช่องทางติดต่อ)"
    8. **ไฟล์แนบ**: JobBKK ต้องดาวน์โหลดได้ครบทุกไฟล์ + รูป (ลอง 2 ครั้ง) ไม่ครบ = ไม่เก็บ "ไฟล์แนบไม่ครบ" (เกิดหลังขอดูเบอร์แล้ว เครดิต JobThai เสียเปล่าได้) · JobThai ต้องการแค่รูปโปรไฟล์
    9. บันทึกคน + แหล่ง + ไฟล์ ในธุรกรรมเดียว · นับความคืบหน้าเฉพาะคน "ผ่านเกณฑ์" ใหม่ของใบนี้
    10. โดนบล็อก → cooldown 2 ชม. หยุดรอบ · error อื่น → ข้ามคนนั้น
12. **จบรอบ**: ได้ไม่ครบ = partial · เปิดแล้วได้ 0 → ข้อความ "เว็บให้มา N คน เปิดดู M คน แต่ถูกคัดออกทั้งหมด · <เหตุ+จำนวน>" · ออกจากระบบ (JobBKK ไม่เช็กว่าออกสำเร็จ) ปิดเบราว์เซอร์ · บันทึกสถิติรอบ (ตัวกรองที่ติด/ไม่ติด อยู่ใน search_metadata) และ "บทเรียน"
13. รอบล้ม/ถูกพัก → ใบ error (ถ้าพักมีเวลาบอก "บัญชีพักถึง …")
14. **รอบขยาย** (ถ้ายังไม่ครบเป้าและรอบแรกไม่ใช่ "เปิด ≥ 10 ใบ ผ่าน 0 ตรวจเพิ่ม 0")
    - ใบจากเนื้องาน: ไล่ตำแหน่งที่ AI ให้ทีละชุด (JobBKK 3 ตำแหน่ง/รอบ · JobThai 1/รอบ) ล็อกอินใหม่ทุกรอบ (หน้าเว็บจะกระโดดกลับไป "ล็อกอิน")
    - หยุดเมื่อ ครบเป้า / โควตาเต็ม / รอบไหนเปิด ≥ 10 ผ่าน 0 (กัน "วนตำแหน่งเผาโควตา" แบบ 2 พ.ย.)
    - ใบที่มีชื่อตำแหน่งตรง ๆ: ขยายด้วยตำแหน่งใกล้เคียง 🟢 ไม่เกิน 6 รอบ
15. **คิวลองซ้ำ**: ใบ error ลองใหม่ได้ 3 ครั้ง (เว้น 30 วิ, 60 วิ · ถ้าถูกพักรอจนพ้นเวลา +1 นาที) ทุกครั้งเริ่มใหม่ตั้งแต่วางแผน AI และล็อกอิน · ครบ 3 ครั้ง = error ถาวร (แจ้งเตือนเฉพาะถ้าตั้ง webhook)

## ขั้น 5–6 อ่านเอกสาร + เติมข้อมูล (RM009 → Ollama)

16. **OCR** ไฟล์แนบ ด้วยโมเดลในเครื่อง (typhoon-ocr หรือโมเดลชื่อมี "ocr") PDF ไม่เกิน 6 หน้า
    - ไม่มีโมเดล / ไม่มี pdftoppm / Ollama ล่ม → ไฟล์ค้าง "รอ" (ไม่ล้ม) worker กลับมาอ่านทุก 10 นาที · ไฟล์ doc/docx → ข้าม · **การเรียก OCR ไม่มี timeout** (ค้างได้)
17. **เติมข้อมูล**: เอาข้อความ OCR เติมช่องว่าง + ดึงเบอร์/อีเมล/LINE · **ไม่คัดเกณฑ์ซ้ำ** คนที่ลดเป็น "ไม่มีช่องทางติดต่อ" ยังค้างสถานะเดิมแม้ OCR เจอเบอร์
18. **ปิดใบ**: ได้ครบเป้า = done · ไม่ครบ = partial พร้อมข้อความ "ยังไม่ครบเป้า: ผ่าน X/เป้า · ต้องตรวจเพิ่ม N · ไม่ผ่าน R" หรือ (ถ้าหยุดเพราะผ่าน 0) "ระบบหยุดค้นตำแหน่งอื่นแล้ว… รอแก้เงื่อนไข แล้วกดรันตอนนี้"

## ขั้น 7 ตรวจรับ (เว็บ)

19. **คนสรรหาดู** หน้า `/scraping/<ใบ>`: สถิติ เปิดดู/ผ่าน/ต้องตรวจเพิ่ม/ไม่ผ่าน/เป้า · ข้อความเหตุเป็นภาษาคน · แก้เกณฑ์ได้ · ปุ่ม **รันตอนนี้** (partial/error) · ปุ่ม **ยืนยันข้อมูลผู้สมัคร** → ตรวจรับ + Jarvis เป็น "เสร็จ"
    - หน้า `/candidates/jobs/<ใบ>`: เรียง ผ่าน → ต้องตรวจเพิ่ม → ไม่ผ่าน · **ซ่อนคนที่ไฟล์แนบ/รูปไม่ครบ** (คน JobThai ไม่มีรูปจะนับเป็นผ่านแต่ไม่โชว์ — จุดอ่อน) · เปิดดูคน = บันทึก "ดูแล้ว" · ปุ่ม "โทรแล้ว"
    - ไม่มีทาง "ไม่รับผล" จากหน้าจอ (มีแต่ป้าย)
20. **Jarvis ดึงสถานะ** เอง (`/status`): ขั้น N/7, ผ่าน/ต้องตรวจเพิ่ม/ไม่ผ่าน, ข้อความ error ดิบ, ลิงก์ใบงาน · ระบบ **ไม่ส่งอะไรไปหา Jarvis เองเมื่อล้ม**

## จุดบอด: สิ่งที่เรามองไม่เห็น

1. เครดิต/โควตาจริงของเว็บ: เรานับเฉพาะ "เปิดสำเร็จ" ตอนจบรอบ การรีโหลด ลองซ้ำ AI Search และกดดูเบอร์ JobThai อาจถูกเว็บนับแต่เราไม่นับ
2. ทำไม JobBKK ซ่อนเบอร์บางคน (ต้องสงสัยว่าบัญชีถูกจับตา) — เรารู้แค่ "ไม่มีเบอร์"
3. ทำไม JobThai ส่งข้อความ "เพื่อความปลอดภัย ติดต่อเจ้าหน้าที่" แทนเบอร์
4. คนใช้บัญชีเดียวกันพร้อมบอท: บอทเตะคน คนเตะบอท (บอทล็อกอินซ้ำได้ 8 ครั้ง)
5. ความหมายของตัวเลขผลค้นบนเว็บ และลำดับ "ใหม่สุด" เมื่อเช็กไม่ได้
6. เว็บเปลี่ยนหน้า: รู้เมื่อหยุดด้วย `JOBBKK_FILTER_NOT_APPLIED` / `SITE_CONTRACT_CHANGED` / timeout เท่านั้น (ต.ค.–พ.ย. พัง 4 รอบ: จังหวัด → ชิปตำแหน่ง → อายุ → อายุอ่านผิด)
7. CAPTCHA / ระงับบัญชี / แพ็กเกจหมด: รู้จาก 429/403 และข้อความเท่านั้น พัก 2 ชม. เป็นค่าเดา ไม่ใช่โทษจริงของเว็บ
8. ออกจากระบบสำเร็จไหม ไม่เช็ก
9. ผู้สมัครเปลี่ยนใจ/ได้งานแล้ว หลังเราเก็บ ไม่มีการเช็กซ้ำ
10. Jarvis เอาสถานะไปแสดงอย่างไร
11. Ollama ล่มระหว่าง heartbeat และ OCR ค้าง (ไม่มี timeout)

## จุดอ่อนที่เห็นจากการไล่ (ยังไม่แก้ ไม่ใช่บั๊กเร่งด่วน)

- โควตาวันเต็มไม่ถูกเช็กตอน Jarvis สั่ง → สั่งผ่าน แล้วรอบล้ม 3 ครั้งใน 1.5 นาที ไม่รอข้ามวัน
- เข้าคิวไม่สำเร็จ แต่ Jarvis เป็น "กำลังทำ" แล้ว → คนสั่งซ้ำจาก Jarvis ไม่ได้ ต้องมากดในเว็บเรา
- ใบงานที่ค้างเพราะเครื่องปิด ไม่ถูกรับต่อเองเมื่อเครื่องกลับมา
- จำนวนคนที่สั่งใน Jarvis ไม่ถูกใช้ (เป้า 20 เสมอถ้า ERP ไม่มี)
- JobThai จังหวัดไม่รู้จักรหัส = ค้นทั้งประเทศเงียบ ๆ · สมุทรปราการได้ 0 ทุกครั้ง
- ข้อความ "ระบบจะค้นต่อเองหลังเวลานั้น" จริงเฉพาะถ้ายังเหลือรอบลองซ้ำ
- คน JobThai ไม่มีรูป นับเป็นผ่านแต่ไม่โชว์ในรายชื่อ
- เติมข้อมูลหลัง OCR ไม่คัดเกณฑ์ซ้ำ คนที่ได้เบอร์จาก OCR ยังค้าง "ไม่มีช่องทางติดต่อ"
